# Link Memo 계층형 PKM 그래프 유지보수 안내

이 문서는 Link Memo의 탭, 소분류, 버튼을 PKM 그래프로 투영하는 구조와 변경 규칙을 설명한다. 파생 인덱스에는 그래프 생성에 필요한 제목·요약·키워드만 기존 PKM 저장 경계 안에서 보관한다. 계정 식별자, API 키, 인증 토큰, 비공개 서비스 주소는 문서나 파생 그래프 파일에 기록하지 않는다.

## 계층별 책임

### 화면 계층

- `pkm.html`: 검색 상태 범례, 노드 유형 범례, `graphTooltip` 호스트를 제공한다.
- `styles/pkm.css`: 범례와 툴팁의 반응형 위치·글꼴을 담당한다.
- `src/presentation/pkm/graph-view.js`: 노드 색상과 모양, 검색 테두리, PC hover 및 비PC 첫 탭 툴팁, 두 번 탭 파일 열기를 담당한다.
- 버튼 노드 라벨에는 제목과 핵심 키워드만 표시한다. 핵심 내용은 툴팁의 일반 텍스트로만 표시해 HTML 삽입과 그래프 과밀화를 방지한다.

### 처리 계층

- `src/presentation/pkm/app-controller.js`: 파생 JSON 인덱스를 검색 메타데이터 대상에서 제외하고 그래프 투영을 조정한다.
- `src/application/pkm/link-memo-vault-projector.js`: Link Memo 버튼 하나를 Markdown 하나로 변환하고 파생 인덱스를 300개 항목 단위로 나눈다.
- `src/application/pkm/graph-projector.js`: 대분류, 소분류, 버튼, 계층 간선, 유형 간선, 키워드 간선을 생성한다.
- `src/application/pkm/graph-worker.js`: 간선 종류별 거리와 인력을 적용하고 규모에 따라 반복 횟수를 줄인다.

### 핵심 규칙 계층

- `src/domain/pkm/link-memo-keyword-policy.js`: 콘텐츠 유형, 색상, 로컬 키워드, 요약, 해시태그, 결정론적 해시 규칙을 소유한다.
- `src/domain/pkm/keyword-synonyms.json`: 외부 API 없이 사용하는 대표어와 유의어를 관리한다.
- `src/domain/pkm/graph-limits.js`: 노드 100,000개, 간선 500,000개 및 레이아웃 반복 횟수를 한곳에서 관리한다.

### 저장 및 외부 서비스 계층

- `src/infrastructure/pkm/schema-discovery.js`는 Firestore의 Link Memo 원본을 읽고 변환 함수에 위임한다.
- 기존 PKM Vault의 IndexedDB와 Firestore 동기화, Drive 이미지 참조, 3분 유휴 저장 규칙은 변경하지 않는다.
- OpenAI API를 포함한 유료 또는 외부 키워드 API는 사용하지 않는다. 사용자 메모는 키워드 추출 목적으로 외부에 전송되지 않는다.

### 의존성 연결 및 앱 시작 계층

- `src/bootstrap/pkm-main.js`의 인증 및 저장소 조립 순서는 유지한다.
- 인증 후 PKM Vault와 Link Memo 원본을 불러오고, 버튼별 투영을 병합한 다음 그래프를 만든다.
- 사용자 세션이 바뀌면 기존 캐시, Vault, 그래프를 초기화하는 경계를 유지한다.

## 노드 구조와 색상

| 노드 | 색상 |
| --- | --- |
| 대분류 | `#F6E7FF` |
| 소분류 | `#B9BFFF` |
| 텍스트 | `#CBEFFF` |
| 링크 | `#F8D374` |
| 이미지 | `#FF9797` |
| 링크+이미지 | `#DE6863` |
| 링크+텍스트 | `#82CFFD` |
| 이미지+텍스트 | `#8ED2CD` |
| 링크+이미지+텍스트 | `#DE6863` |

버튼 제목은 모든 버튼의 표시명일 뿐 텍스트 조합 판정에 포함하지 않는다. 댓글, 설명, 본문 또는 노트가 있어야 텍스트가 있는 것으로 판정한다.

## 파일과 파생 인덱스

버튼 파일은 다음 경로를 사용한다.

```text
Link Memo/<대분류>/<소분류>/<안정적인 버튼 ID>.md
```

버튼 ID가 있으면 그대로 사용하고, 없으면 소분류·제목·URL·댓글을 기반으로 결정론적 ID를 만든다. 배열 순서만으로 ID를 만들지 않는다.

`Link Memo/.graph-index.json`은 파생 인덱스 조각 목록을 가진다. 실제 항목은 다음처럼 나눈다.

```text
Link Memo/.graph-index/00001.json
Link Memo/.graph-index/00002.json
```

각 조각은 최대 300개 항목을 담아 기존 파일당 2MB 제한을 넘을 가능성을 줄인다. 인덱스는 검색 및 일반 파일 노드에서 제외되며 원본 Link Memo로 다시 만들 수 있다.

## 키워드와 요약

- 키워드는 브라우저 안에서 해시태그, 제목, 본문, URL, 이미지 이름 순으로 점수를 계산한다.
- 유니코드 NFKC, 영문 소문자화, 불용어 제거, 중복 대표어 제거를 적용한다.
- 버튼당 최소 3개, 최대 7개를 만든다. 실제 후보가 부족할 때만 제목, 대분류, 소분류, 콘텐츠 유형을 순서대로 보완한다.
- 요약은 생성형 문장을 만들지 않고 원문 첫 핵심 문장, 이미지 이름 또는 URL에서 추출한다.
- 노드에는 제목과 앞의 핵심 키워드 3개만 표시한다.
- PC에서는 버튼 노드에 마우스를 올렸을 때, 비PC에서는 첫 번째로 눌렀을 때 요약 툴팁을 표시한다. 같은 노드를 빠르게 두 번 누르면 기존처럼 Markdown 파일을 연다.

## 간선 규칙

- `category-membership`: 대분류에서 소분류로 연결한다.
- `subcategory-membership`: 소분류에서 버튼으로 연결한다.
- `same-link-type`: 같은 소분류 안의 링크 계열 버튼을 연결한다.
- `same-image-type`: 같은 소분류 안의 이미지 계열 버튼을 연결한다.
- `keyword-related`: 정규화 또는 유의어 대표어가 같은 버튼을 연결한다.
- `wiki-link`, `canvas-file`, `canvas-link`: 기존 사용자가 만든 연결을 유지한다.

텍스트 전용 버튼은 유형만으로 서로 연결하지 않고 `keyword-related` 또는 기존 사용자 링크가 있을 때만 연결한다. 한 관계 그룹이 32개 이하이면 완전 연결하고, 그보다 크면 각 노드를 가까운 두 이웃과 연결해 간선 폭증을 막는다.

## 검색과 표시

검색 직접 일치는 노드 배경을 바꾸지 않고 파란 테두리와 그림자로 표시한다. 1-hop 문맥은 하늘색 테두리, 미일치는 낮은 투명도를 사용한다. 따라서 검색 중에도 유형 색상이 유지된다.

## 사용자 편집 보호

파생 인덱스에는 마지막 자동 생성 Markdown의 해시가 들어간다.

- 현재 파일 해시가 마지막 생성 해시와 같으면 새 Link Memo 원본으로 안전하게 갱신한다.
- 다르면 사용자가 편집한 파일로 보고 자동 덮어쓰지 않는다.
- Link Memo에서 삭제된 버튼의 파일도 수정되지 않은 자동 생성 파일만 tombstone으로 정리한다.
- 편집된 파일은 원본 버튼이 삭제돼도 자동 삭제하지 않는다.
- 보호된 편집 개수는 파일 패널의 스키마 요약에 표시한다.

## 규모 제한과 성능

- 최대 노드: 100,000개
- 최대 간선: 500,000개
- 5,000개를 넘는 그래프는 화면 맞춤 애니메이션을 생략한다.
- 레이아웃 반복은 3,000개, 5,000개, 20,000개, 50,000개 경계에서 단계적으로 줄인다.
- 계층 간선을 먼저 만들고 유형·키워드 간선을 뒤에 만들어 한도에 도달해도 소속 관계를 우선 보존한다.

상한은 수용 가능한 입력 경계이지 모든 모바일 기기에서 100,000개 노드를 부드럽게 표시한다는 성능 보장은 아니다. 실제 데이터 규모별 성능은 별도로 측정해야 한다.

## 검증 절차

1. `tests/pkm-link-memo-graph.test.js`에서 유형, 색상, 키워드, 계층 간선, 사용자 편집 보호, 상한, 툴팁 계약을 검증한다.
2. `npm test`를 실행한다.
3. `npm run build`를 실행한다.
4. 보안 diff에서 사용자 텍스트가 `innerHTML`로 들어가지 않는지, 인덱스에 비밀값이 포함되지 않는지 확인한다.
5. 배포 후 PC hover 툴팁, 비PC 첫 탭 툴팁, 두 번 탭 파일 열기, 검색 색상 보존을 확인한다.
6. Playwright는 이 기능의 검증 범위에서 제외한다.

## 확장 규칙

- 유의어는 `keyword-synonyms.json`에 대표어와 변형을 추가한다.
- 새 콘텐츠 유형을 추가할 때 분류, 색상, 범례, 테스트, 이 문서를 함께 갱신한다.
- 외부 AI 분석을 추가하려면 별도 사용자 승인, 비용 상한, 서버 측 비밀 관리, 외부 전송 동의, 실패 대체 경로를 먼저 설계한다. 무료가 보장되지 않는 API를 기본 경로에 연결하지 않는다.
